# 0086 样例（2026-09-16）

## 推理链

最初主线“多翻一页菜单”突出菜单多样性；用户补充店外“无辣不欢”后，确认“香辣”作为编辑定位。招牌是店方表达，顾客材料支撑辣子鸡的酥脆与辣麻等具体特点。保留鱼菜、粉蒸、内脏、蔬菜和甜口，避免把餐厅只写成辣度挑战。

标题：为这一口香辣。

卡片：从辣子鸡的酥香麻辣吃起，配上水煮鱼、粉蒸和蔬菜，凑成一桌川味。

正文以香辣开篇，再介绍粉蒸与内脏、蔬菜与甜口，最后回到一桌菜的组合。图片跟随主题：鱼菜、辣子鸡、粉蒸肉、红糖糍粑、餐桌空间。不要将这些菜或顺序套用到其它餐厅。

## 读者语言

不佳：较新的德语选样补充了这条线索。

合适：食客评价中提到的特点包括酥脆的口感，以及辣椒与花椒带来的香辣和麻感。

不佳：某某来过后……另一个餐饮账号来过后……

合适：把支持同一特点的评价归纳在一起；若是单个食客的点餐组合，明确是个别经验，不伪装成多来源结论。

读者说明示例：本文由 Pinwo 根据餐厅菜单、媒体报道与食客评价整理，帮助你了解这家餐厅和选择菜品，并非编辑亲访餐评。

## 新餐厅底稿最小结构

按任务规模使用 Markdown 或 JSON，避免维护重复副本。

1. 身份：餐厅名、分店、地址、packet 路径、页面。
2. 来源：ID、URL、来源类型、发表/采集日期、可读范围、摘要或必要短摘、重复关系。
3. 证据：主张、来源 ID、事实/顾客感受/媒体观察/编辑判断、相反材料、可信范围。
4. 关键词：候选词、支持与限制、最终定位及用户输入。
5. 文案：长文、卡片句、标签；保留段落与证据的对应。
6. 图片：来源、授权状态、原图、编辑输出、处理方式、文章位置。
7. 交付：代码与预览路径、验证结果、未解决事项、是否部署。
